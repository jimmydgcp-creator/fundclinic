# 基金复诊台 FundClinic v2

> 给〔基民 / 基金公司初步评价考核 / FOF 初步评价〕用,把〔一只公募基金的代码 + 复盘区间〕变成
> 〔一份可核验的"十大持仓回溯复盘报告"网页 + 一份能直接发给别人的演示稿〕。
>
> 输入一个 6 位基金代码 → 自动按 SOP §2 六类来源抓取 → 官方季报 PDF 逐行对账 + 官方窗口校准 →
> 出报告 MD、结论卡、错误检查记录、来源清单,以及**由 AI 按内容编排的单文件 HTML 演示稿**与 PDF。

---

## 〇、两种演示稿:模板版 vs 深度版

同一只基金会出两份 HTML 演示稿,分工不同:

| | `演示稿_<名>_<代码>.html` | `演示稿_<名>_<代码>_深度版.html` |
| --- | --- | --- |
| 谁做的 | **规则引擎**(`server/deck.mjs`) | **大模型**(`server/deckagent.mjs`,T6) |
| 怎么做 | 版式写死,只把数字填进固定槽位 | 读完整报告 → **分镜**(讲几页、每页主张什么、用哪个版面)→ **逐页单独成文** |
| 观感 | 稳定、信息全,但一眼是报表 | 每页标题是一句主张,版式随内容变,有讲者备注 |
| 依赖 | 无 | 需要 API Key |
| 页数 | 固定 9 页 | 8–11 页,由内容决定 |

**深度版的设计系统来自 `skills/html-ppt` 技能**(36 套主题 / `base.css` / 版面组件),
生成时全部内联进一个文件 —— 发给别人双击就能看,断网也能看,`T` 键还能换主题。

> 为什么要做两套:模板版永远可用,是保底;深度版才是拿得出手的那份。
> 如果大模型调用失败,**深度版会跳过,模板版照常产出**,不会因为一次接口抖动就什么都没有。

## 一、怎么跑起来

### 路线 A · 在线模式(推荐,能自动爬取)

双击 **`启动_基金复诊台.bat`**,浏览器会自动打开 `http://127.0.0.1:8787`。流程是**两阶段**:

| 步骤 | 做什么 | 耗时 |
| --- | --- | --- |
| ① 输入基金代码 | 在左栏填。**Key 不用填** —— 已在项目里的 `llm.local.json` 配好, 服务端启动时自己读 | — |
| ③ 点「开始复盘」→ **探路** | 只抓元数据: 基金概况 / 历任经理(含共管期) / 报告期网格。**不抓持仓、不抓 PDF** | 约 0.5 秒 |
| ④ **口径确认表**(SOP §0 八格) | 表已自动填好候选值,你只做确认或改: **复盘哪一任经理、哪个区间**、数据截止日、业绩比较基准、收益口径… | 你决定 |
| ⑤ 点「按此口径开跑」 | 按你确认的口径跑完整流程,出报告与演示稿 | 约 10 秒 |

> 为什么要停这一下: SOP §0 的原话是「**任何一格留空不许开跑**」。原版是 AI 口头问你,网页版把候选直接列出来让你点 ——
> 不用打字,也不会理解错。尤其**共管期**: 005827 现任经理 2026-05-23 才接手(仅 1 期),引擎会建议改用张坤那一任(30 期),
> 但**最终由你拍板**,不再由引擎偷偷替你换。
>
> 若你选的区间端点没有前十大持仓数据(如刚成立的季度只有季报),引擎会对齐边界并**在报告里写明被调整过**,不会悄悄少算。

**结果会自动存下来** —— 跑完落盘到 `_runs/<代码>/`,左栏「已复盘」里点一条就能把这卷结果调回来(不重跑、不花额度)。
刷新、按浏览器回退、关掉浏览器、甚至重启服务,回来都还在;点「载入」即可恢复,不用重跑。

> 下载按钮走的是浏览器下载(blob),**不会跳走页面**;在线预览一律开新标签页 —— 所以不会出现"点一下结果就没了"。

> 需要本机有 Node.js(https://nodejs.org 下载 LTS 版即可,装完重新双击 bat)。
> **AI 模块是必选的**(见下),所以要有一个大模型 API Key:官方地址 <https://platform.deepseek.com>,
> 默认 `Base=https://api.deepseek.com`、`模型=deepseek-v4-flash`。
> 这台机器已经把 Key 写进 `llm.local.json`(见下),所以**页面上没有 Key 表单, 也不需要填**。

命令行等价写法:

```bash
node server.mjs            # 默认 8787;端口被占会自动往后试
```

**Key 只配一次, 配好之后页面上不再出现**(整块表单会被收掉, 连"申请 / 测试连通性 / 记住"这些字都不会出现)。
当前这份项目目录里已有 `llm.local.json`, 直接双击启动即可。换一台电脑 / 发给组员时, 三处任选其一:

```bash
# ① 环境变量(推荐给命令行用户)
set FUNDCLINIC_LLM_KEY=sk-xxxx        # Windows
export FUNDCLINIC_LLM_KEY=sk-xxxx     # macOS / Linux

# ② 项目目录下建 llm.local.json(模板见 llm.local.json.example)
{ "baseUrl": "https://api.deepseek.com", "model": "deepseek-v4-flash", "apiKey": "sk-xxxx" }

# ③ 页面上填, 勾选"记住"存进本机浏览器 localStorage
```

### 路线 B · 离线单文件(零依赖,永远打不开网络也能用)

直接双击 **`基金复诊台_单文件版.html`**。
不联网、不装任何东西,内置两只已对过账的样例基金,也支持粘贴自己的季报持仓表。
**答辩/演示时建议用这一版兜底** —— 它不依赖网络与任何外部服务。

> 为什么在线模式必须有个本地服务:浏览器不允许网页从 `file://` 跨域抓取天天基金的数据(CORS),
> 这是浏览器的安全模型决定的,前端怎么写都绕不过去。把抓取放到本地 Node 进程里就没有这个限制。

### 路线 C · 云端演示(不跑也能看)

公网那台(Render)的容器磁盘是**临时的**:重新部署、或休眠后重启,`_runs/` 会被清空 ——
打开页面就是空的,问一句得到「这只基金还没有跑过复盘」,必须现场真跑 6–7 分钟才有内容(还花 token)。
所以仓库里放了一份**预置跑批** `_seed/<基金代码>/`:两只真跑过的基金(一只主动、一只 ETF),
报告 / 演示稿 / 结论卡 / 来源清单全套都在。云端启动时自动补进 `_runs/` —— **只补不覆盖**,
已经存在(不管是种子还是你真跑的)就跳过。细节与更新办法见 [`_seed/README.md`](_seed/README.md)。

| 场景 | 会不会自动加载 `_seed/` |
| --- | --- |
| 本机双击启动(默认) | **不会** —— 免得你电脑上突然多出两只不是自己跑的基金 |
| 本机想看种子效果 | `FUNDCLINIC_SEED=1 node server.mjs`(也可以用 `FUNDCLINIC_SEED=0` 在云端强制关掉) |
| 云端(Render 等) | **会**,启动横幅会写「预置: 已就位 N 只(…) —— 重新部署后秒开, 不用现场跑」 |

要更新种子:真跑一次 → 把 `_runs/<代码>/` 里对应的文件覆盖到 `_seed/<代码>/` 再提交。
**不要把 PDF 放进 `_seed/`**(单个文件就 1–3 MB,它只影响"能不能下载 PDF",而演示稿自己按 `P` 就能打印)。

### 页面上还能做什么(期末新增的四块)

| 能力 | 在哪 | 一句话说清它在干嘛 | 它不管什么 |
| --- | --- | --- | --- |
| **问一句** | 左栏底部「问一句」/ `POST /api/ask` | 拿这只基金报告里**已有的字段**回答追问:净值怎么走的、持仓怎么变的、哪期偏离大。每个数字后面必须跟 `〔字段id〕` | 不预测涨跌、不推荐买卖、不评价基金经理个人 —— 命中就拒答 |
| **横向对比** | 左栏底部「横向对比」/ `POST /api/compare` | 输 2–3 个代码,只抓净值、不跑全流程,统一口径为分红再投总回报指数,起点归 100,区间取重叠部分 | 不做归因;被动 ETF 与主动基金不比形态标签 |
| **持仓拟合** | 报告里《持仓拟合》一节 | 拿每季末前十权重 × 这些股票下一季的真实涨跌,算出"如果经理一直没动,这只基金应该怎么走",再与实际净值比残差 | 不归因。残差只能提示"可能发生了什么",不能证明是调仓还是打新/杠杆/费用 |
| **产品类型** | 报告里《产品类型》一节 | 先判定这是主动管理 / 指数 / ETF / ETF 联接 / 跨境 / 货币 / 债券,再决定后面各节该怎么读 | 被动产品不看形态标签,改看跟踪误差、跟踪偏离、费率与折溢价 |

还有一条贯穿全站的约定:**数字红涨绿跌**(A 股习惯)。实现上分得很干净 ——
方向性数字用 `.up` / `.down` 两个专用类,而 `.pos` / `.neg` 仍然是**状态标签**的语义色
(逐行一致 / 未通过 / 本次采用)。这两套颜色不能混用:混用过的后果是"未通过"变成绿色、
"逐行一致"变成红色,语义正好反。

> 这四块都是"报告里已有的东西换个问法",没有一块去猜未来。问答与拟合的数字都必须能回查到字段/证据包,
> 回查不到就不给。

### 界面结构:两栏(2026-11-08 改版)

页面从"顶部 6 个横排标签 + 整页滚动"改成了两栏,样式全在 `app/shell.css`(内容样式仍在 `app/styles.css`,两张表互不写对方的选择器):

| 位置 | 放什么 | 为什么放这儿 |
| --- | --- | --- |
| 左栏(288px) | 新建复盘 / 基金代码输入 / 当前口径摘要 / 已复盘的基金 / 报告目录 / 横向对比 · 问一句 · 内置样例 · 说明 | 这五件事都是"反复要做"的。原来的横排标签在 1440px 窗口下就会折行,代码输入框还被埋在首屏下半页;跑过的基金更是藏在输入页最底部 |
| 顶栏(52px) | 现在看的是哪只基金(名称 · 区间 · 期数) + 分段控件(开工台 / 复盘报告 / 数据底稿 / 质检) | 切换同一只基金的三种读法,不需要再回"输入与口径"页 |
| 主区 | 开工台(探路结果 + 八格口径 + 开跑 + 步骤条 + 日志)或一份报告 | 原来的整页滚动改成区内滚动,读报告时左栏目录会跟着高亮当前章节 |

两条硬约束(踩过,记在这儿):

- **打印 / 导 PDF 时外壳整体退场**:两栏用的是 `100vh + overflow:hidden`,不写 `@media print` 兜底,导出的 PDF 会只剩一屏(上一次的教训是"PDF 11 页一个字都没有")。`tools/check_pdf_text.mjs` 会逐字比对抓住这类问题。
- **报告目录只留一份**:目录搬进左栏后,正文里就不要再放第二个左侧目录,否则两栏并排成"两个左栏"。读报告时左栏中段自动从"已复盘"切成"这份报告的目录"。

## 二、数据从哪里来(严格按 SOP §2)

**官方定期报告 PDF 是最高权威,天天基金只做第三方交叉验证。** 六类来源与对应接口:

| # | 来源 | 接口 | 取到什么 |
| --- | --- | --- | --- |
| ① | **官方季报/年报 PDF** | `api.fund.eastmoney.com/f10/JJGG?fundcode={code}&type=3` 列报告 → `pdf.dfcfw.com/pdf/H2_{ID}_1.pdf` 取原文 → `pdftotext` 抽文本 | 前十大持仓表、**经理原话**(投资策略和运作分析)、期末份额净值 |
| ② | 天天基金历史前十大 | `FundArchivesDatas.aspx?type=jjcc&code={code}&topline=10&year={年}` | 逐季前十大(排名/代码/名称/占净值/持股数/持仓市值) |
| ③ | 天天基金资产配置 | `zcpz_{code}.html` | 股票/债券/现金占净比 |
| ④ | 天天基金规模变动 | `FundArchivesDatas.aspx?type=gmbd&code={code}` | 期末份额/期末净资产 |
| ⑤ | 净值序列 | `fund.eastmoney.com/pingzhongdata/{code}.js` | 日频单位净值 + 累计净值(两者都要,用来还原分红) |
| ⑥ | 经理履历 | `jjjl_{code}.html` | 历任经理、上任/离任日、**共管搭档** |

### 官方对账是硬动作,不是声明

SOP §2 要求「官方 PDF 与第三方接口至少重合 1 季,逐行对账,对不上的以官方 PDF 为准并记录差异」。
本项目把这条做成了自动动作:自动挑选**首季、末季、每 4 季抽样**,下载官方 PDF、抽出前十名股票投资明细表、
与第三方数据**按股票代码**逐行比对(权重容差 ±0.011pp),结果写进报告与来源清单。

实测:519191 官方对账 **4/4 期逐行一致,权重最大差 0.000pp**;005827 同样 **4/4 期一致**。
本机没装 Poppler 时,这一项会**如实标记为"未完成"**,不会假装对过账。

## 三、收益口径(重要,v2 修正了一个真实错误)

> ⚠️ **下面这一段是我们自己踩过的坑, 而且是"错了两遍"才改对的。留在这里当反面教材。**

**不能用累计净值算收益。** 累计净值 = 单位净值 + 累计分红,是**加法**累积量,拿它做比值在数学上无意义。

v2 改用**分红再投总回报指数**:用单位净值,并在除息日把当日每份分红加回去,链式相乘。
以 519191 的 2026Q2 季报 §3.2.1 披露值为标尺:

| 窗口 | 官方披露 | 累计净值法(v1) | 偏差 | **分红再投指数(v2)** | 偏差 |
| --- | --- | --- | --- | --- | --- |
| 过去三年 | +35.10% | +28.33% | −6.77 | +35.10% | **0.00** |
| 过去七年 | +99.93% | +73.80% | −26.13 | +99.93% | **0.00** |
| 过去十年 | +175.19% | +129.07% | −46.12 | +174.23% | **−0.96** |
| **平均绝对偏差** | — | — | **15.94pp** | — | **1.07pp** |

#### 然后我们把"改对了口径"和"改错了起点"混成了一件事

修完口径后, 519191 的区间收益从 +76.77% 变成 **+85.97%**, 我们当时把这当成"修正"写进了文档。
**它是错的。** 真正的错误在另一处: 复盘区间是 2020Q4–2026Q2, 但基准点错取了
2020-12-31(2020Q4 的**期末**) —— 于是第一个季度自己的收益被整个漏掉。

把基准点改成「**第一个报告期的期初**」(2020-09-30) 之后:

| | 值 | 说明 |
| --- | --- | --- |
| 区间收益(v3, 2020Q4–2026Q2) | **+76.80%** | 与最初手工算的 +76.77% 一致(差 0.03pp 是现金分红日取整) |
| 逐季与官方季报对账 | **22/22 期一致** | 最大偏差 0.01pp |
| 最大回撤 | −32.45% | 与人工核对值一致, 两次修正都没动过它 |

> **区间延到 2026Q3 之后**(24 期、23 期官方 PDF 对账 230 行): 同一套口径下区间收益 **+119.36%**,
> 剔除最好一季 68.10%, 最大回撤不变。上面 76.80% 是修正当时(只到 2026Q2)的数, 别当现值念。
> 内置样例 `data/funds.data.js` 已于 2026-11-08 同步到 Q3(见 `tools/sync_sample_519191.mjs`),
> 现在「内置样例」与「最近的复盘记录」是同一份数据, 不会再出现同一只基金两个数字。

**怎么发现 85.97% 是错的**: 如果它是对的, 每个单季收益都该比官方季报高 —— 但实测逐季与官方**完全吻合**。
所以错的不是收益算法, 是**起点**。官方**逐季**披露值把它钉死了。

> 一条写进代码注释的教训:
> **工具给出的数字比手工算的更好看时, 恰恰是最该怀疑它的时候。**

校准脚本: `node tools/calibrate_perf.mjs 519191`。详见 `SOP_基金持仓复盘_标准流程v2.5.md`。

## 四、AI 模块:必选,但输出必须过校验

### 为什么必选

**T1 主题归类没有公开接口可替代** —— 天天基金、巨潮都不提供"主题"字段。
缺了它,形态库里的「主题坚守型 / 主题漂移型」两条规则会直接跳过,形态判定会退化
(实测:519191 缺主题时只能判成"逐步分散型",补上主题后才判出"主题坚守型")。
所以页面强制要求先填 Key 并通过连通性测试,才允许点「开始复盘」;服务端也会在**爬取之前**就拒绝无 Key 的请求。

**但"必选"指的是"必须调用",不是"无条件采信"** —— 大模型的每一份输出都要过校验,不过一律拦截:

| 任务 | 输入 | 输出 | 错了怎么发现 |
| --- | --- | --- | --- |
| **T1 主题归类** | 去重个股清单 | `{mapping:{股票名:主题}, uncertain:[]}` | 覆盖率 ≥95%;映射键不得出现清单外的股票(幻觉新增即判失败);人工确认后才进报告 |
| **T2 核心判断起草** | 引擎算出的指标包 | `{formTag, mainQuestion, claim, falsifier, evidenceUsed}` | 必填字段完整性;claim/falsifier 里每个数字必须能在指标包里找到(否则判编造);形态标签必须在形态库内(含兜底条款);违禁词扫描 |
| **T3 对外用词清洗** | 报告全文 | `{cleaned, replaced}` | **数字守恒**:逐个数字比对,改掉任何一个即作废;清洗后回扫违禁词必须 0 命中;长度不得少于原文 90% |

拦截后不是"报错结束",而是**降级继续**:规则引擎的结论卡照用,报告照出,只是在质检页明确标出"AI 输出未通过校验,已拦截"。
抓取/解析/量化/对账/质检全部交给脚本(确定性、可复现),不经过大模型。

### Key 从哪来(本机已配好, 页面上没有这一块)

Key 只在本地服务进程内存里用一次,**不落盘、不进日志、不出现在 URL 里**;请求由本地服务转发,因此不受浏览器 CORS 限制。
默认指向 DeepSeek 官方接口(<https://platform.deepseek.com>),任何 OpenAI 兼容接口都能换。

### 放到公网:Key 由谁出,决定要不要开闸门

| 模式 | Key 从哪来 | 访客要做什么 | 用量闸门 |
| --- | --- | --- | --- |
| **本机**(默认) | 项目目录里的 `llm.local.json`(或环境变量) | **什么都不用填** | **不启用** —— 各自花自己的钱, 限额没意义 |
| **公网 · 自带 Key** | 访客自己的 | 自己填 Key | 不启用 |
| **公网 · 站方出 Key** | **服务端环境变量 `FUNDCLINIC_LLM_KEY`** | 只输基金代码 | **自动启用**(见下) |

第三种就是"发一条链接, 同学打开输代码就能用"的形态。这种模式下页面**整块 Key 表单会被收掉** ——
访客在左栏只看到"基金代码 + 抓取年数"两格, 加一句"AI 模块由本站服务端提供, 不用申请也不用填写任何 Key";
(本机形态同样收掉表单, 只是那句说明也不显示 —— 本机没有"本站"这回事;)
`/api/health` 的 `llm.hasKey` 为真时前端自动切到这种长相(`app/online.js` 里的 `online.serverKey`),
按钮的可用条件也跟着变成"只要 6 位代码填对"。它把一个花钱的问题摆到台面上:
**Key 变成了任何点开链接的人都能花的钱** —— 链接被爬虫扫到、或者有人反复点, 账单记在你头上。
所以这种模式下 `server/quota.mjs` 会自动开三道闸, 全部可用环境变量调:

| 闸 | 变量 | 默认 | 作用 |
| --- | --- | --- | --- |
| 每台机器每小时 | `FUNDCLINIC_MAX_PER_IP_HOUR` | 3 | 挡住"一个人连点十次" |
| 每台机器每天 | `FUNDCLINIC_MAX_PER_IP_DAY` | 8 | 挡住"一个人跑一整天" |
| **全站每天** | `FUNDCLINIC_MAX_RUNS_DAY` | **40** | **真正兜住账单的那一道** |
| 开关 | `FUNDCLINIC_QUOTA` | 跟随云端判断 | `1` 强制开 / `0` 强制关 |
| 计数落盘位置 | `FUNDCLINIC_QUOTA_FILE` | `_runs/.quota.json` | 想挂到持久卷上就指到那儿 |

另外两个入口(2026-11-01 加)**各有一套独立的轻闸门**。它们不跑全流程, 但一个是"调一轮大模型"、
一个是"发几个抓取请求", 都属于成本最低、最容易被一段 `for` 循环刷的口子:

| 入口 | 每台机器每小时 | 每台机器每天 | 全站每天 |
| --- | --- | --- | --- |
| 页面内问答 `POST /api/ask` | `FUNDCLINIC_MAX_ASK_PER_IP_HOUR` = 10 | `FUNDCLINIC_MAX_ASK_PER_IP_DAY` = 30 | `FUNDCLINIC_MAX_ASK_DAY` = 150 |
| 多基金对比 `POST /api/compare` | `FUNDCLINIC_MAX_COMPARE_PER_IP_HOUR` = 20 | `FUNDCLINIC_MAX_COMPARE_PER_IP_DAY` = 60 | 不设上限 |

为什么必须**分开记**而不是共用一套: 跑一次复盘要调好几轮大模型(几分钟), 问一句只要一轮(几秒)。
共用计数会出荒唐结果 —— 在页面上问了两句话, 那个小时就再也跑不了复盘。
分桶之后每类各挡各的, 既拦得住刷接口的人, 也不打扰正常用的人。
额度填 `0` 的含义是**这一类不设该道闸**(不是"一次都不许")。

被拦时三个入口(`/api/run` `/api/ask` `/api/compare`)走同一个拒绝出口:
**429 + 一句中文原因 + `Retry-After` 头**, 而且都在**真正动手之前**拦下
(不是跑完 20 秒才告诉你超了),
页面上也会在动手前显示"今天还剩几次"。`GET /api/health` 的 `quota` 字段给出
当日已用 / 剩余 / 访客数 / **累计 token**, 以及 `ask` / `compare` 各自的用量。

> 边界写清楚: 额度按**北京时间**跨天;计数落在容器本地磁盘上,所以**平台重新部署会清零**,
> 它是"尽力而为的防呆",不是计费系统。要严格计费得上外部存储,那是另一个工程量。
> `tools/test_quota.mjs` **54 条断言**钉住"该拦的拦住、不该拦的不拦(本地默认完全不管)",
> 其中包含一条关键反证: 跑复盘的额度用完时, 问一句和做对比**不该**跟着一起挂(三桶互不抢占)。

## 六、三道人机门禁(人不可让渡)

> 2026-10-10 界面收敛:门禁的判定标准从"人打勾"改成了"机器结算 + 直接显示"。
> 原因是勾选框**不产生任何证据** —— 它不改数据、不改报告,只把导出按钮从灰变亮,
> 证明的是"有人点过鼠标",不是"有人核过数";公网访客也不是这次复盘的负责人。
> 所以页面上只保留人真正比机器多知道的那两步(口径、判断方向),其余一律把核查结果摆出来。

1. **门禁 1 · 口径确认** —— 机器猜不出来的那几格(复盘哪一任经理 / 起止区间 / 数据截止日 /
   业绩比较基准 / 收益口径 / 只看前十大 / 产出位置)由人定,任何一格留空不许开跑;
   内置样例的口径是固定的,页面直接摆出来给人看,不再要求"勾满三项";
2. **门禁 2 · 核心判断方向** —— 形态标签由引擎给出候选与置信度,报告按此方向成文;
   人工改判连同理由记进结论卡的 `humanOverride` / `humanReason`(不覆盖引擎原判);
3. **门禁 3 · 终审三查** —— 数字查(12 处抽检清单,每条给出官方季报链接与合格判据)、
   结论查(每条结论找得到证据行)、合规查(违禁词扫描 + 免责声明)全部由 18 条质检规则实际结算,
   结果直接显示在「④ 质检与 AI 记录」页 —— 不需要访客替我们打勾。

### 演示稿"内联之后才会暴露"的三个问题(都踩过, 都写在这儿)

单文件演示稿是把 36 套主题 + base.css + animations.css + runtime.js 全部拼进一个 HTML。
拼接这件事本身会制造三类屏幕上看不出来的故障:

1. **导出的 PDF 只有 1 页。** 屏幕态下 `.deck` 是 `height:100vh + overflow:hidden`、`.slide` 是
   `position:absolute + opacity:0`, 靠 `.is-active` 一次只显示一张。打印时只把 `.slide` 改成
   `position:relative/opacity:1` 是不够的 —— `.deck` 还锁在 100vh 且隐藏溢出, 后面全被裁掉。
   2026-10-10 实测: 8 页的演示稿用 headless Edge `--print-to-pdf` 只出 1 页。
   现在打印块会一起放开 `html/body/.deck` 的高度与溢出, 并且**只用一种分页方式**
   (`.slide + .slide{break-before:page}`; 再加 `page-break-after` 会多出空白页)。
2. **打印会丢整块内容。** `animations.css` 里 `.anim-stagger-list > *` 的**基础态**是 `opacity:0`,
   靠 `animation:…both` 抬起来; 打印时动画不跑就永远不可见。同一条教训本项目踩过两次, 解法固定:
   **打印里关掉动画, 就必须同时把 `opacity` 顶回 1**。另外 `.gradient-text` / `.kicker` / `h1.title`
   的透明字填充在 PDF 里会渲染成空白(封面的区间副标题就挂在这个类上), 打印时回落成实色。
3. **主题串味: 选了主题只换变量、不换骨架。** 36 套主题里有 116 条顶层规则不是 `:root` 开的
   (`body`/`.card`/`.kicker`/`.slide`/`.pill`…)。内联时若只改写 `:root`, 这 116 条会**同时生效**,
   谁在源码里靠后谁说了算 —— 于是"瑞士网格"的卡片描边其实来自 academic-paper。
   现在每条规则都加 `[data-theme="名"]` 作用域(`@keyframes` 除外), 由 `test_theme_scoping.mjs` 钉住。

这三条都**只在导出/分发时才暴露**, 所以都做成了机器检查(`lint_print_safety.mjs` / `check_deck.mjs` /
`test_theme_scoping.mjs`), 不靠"我打开看了一眼没问题"。


### 演示稿形态判据的口径(踩过坑, 写在这里免得重犯)

判据只在 `server/deckmetrics.mjs` 定义一处, 度量和门槛都在那里。门槛全部取自用户认可的那份
参照稿(519191 回溯复盘 PPT)的**逐页实测值**, 并留约 25–30% 余量:

| 项目 | 参照稿实测 | 门槛 |
|---|---|---|
| 页数 | 8 | 7–10 |
| 均字数 | 616/页 | ≥550 |
| 加粗 | 54 处(均 6.8, 单页最多 14) | 全篇 ≤70, 单页 ≤16 |
| 卡片 | 22 张(2.8/页, 单页最多 5) | 全篇 ≤28, 单页 ≤6 |
| 指标卡 | 6 个(只在成绩页 4 + 最新季页 2) | 全篇 ≤8, 单页 ≤4 |
| 表格 | 3 张(每张带一列人话) | ≤4 |
| 讲者备注 | 74–116 字 | 40–160 |
| 内容页最长文字块 | 最短 93 字 | ≥90 |
| 段末注记 .sec-note | 每个内容页都有 | 每页必须有 |

**教训**: 2026-10-10 我拿"全篇均值"当"逐页硬顶"(每页 ≥170 字连续论述 / 每页 ≤3 张卡 / 每页加粗 ≤9),
结果这三条会把参照稿自己的 5 个内容页判成不合格 —— 参照稿的绩效页根本没有长论述块, 轮动页 5 张卡,
案例页 14 处加粗。`tools/test_deck_rubric.mjs` 现在**拿参照稿跑一遍并要求 0 条告警**, 就是为了让
"判据误伤参照稿"这类错误立刻变红。

## 九、边界与免责

- 只看**前十大持仓**(公募季报披露口径),不是全部持仓;季报是**期末快照**,期间买卖不可见;
- 推算价 = 期末公允价值 ÷ 期末持股数,**未复权、不含分红**,不代表投资者实际收益;
- 数据仅来自**公开渠道**,不含任何机构或实习单位内部数据;
- 全文为**回溯复盘**,不含对未来收益的判断,**不构成投资建议**,不评价基金经理个人,不推荐任何基金。
