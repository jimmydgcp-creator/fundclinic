# `_seed/` · 云端演示用的"预置跑批"

这个目录里放的是**真实跑批的产物**，不是手写的假数据，也不是样例截图。

之所以要把它放进仓库：跑一次的产出落在 `_runs/<代码>/`，而 `_runs/` 是 `.gitignore` 的本地过程产物，
**不进仓库**。Render 免费档的容器磁盘是临时的 —— 每次重新部署、或休眠后重启，`_runs/` 就清空了。
结果是演示时打开公网地址，报告页是空的，问一句会答「这只基金还没有跑过复盘」，
必须现场真跑 6–7 分钟才有内容（还花 token）。2026-11-01 一天里就撞到两次。

所以：**把跑批结果烤进镜像**。容器一起来，服务发现 `_runs/<代码>/` 不存在，就从这里复制一份过去。
打开就是有东西看的状态，不用现场跑、不用现场烧 token。

两只基金是**故意配的一对**：一只主动、一只被动，正好演示报告里「产品类型」那一节怎么改变读法
（主动基金看形态标签与轮动，ETF 改看跟踪误差、费率、折溢价）。单放一只主动基金，这件事讲不出来。

每只目录里保留的都是**交付物本身**（和 `_runs/<代码>/` 下同名同内容）：

- `analysis.json` `check.json` `datasetMeta.json` `run.json` —— 服务读取的落盘结果
- `复盘报告_*.md` / `复盘报告_*_对外版.md` / `来源清单_*.md` / `错误检查记录_*.md` / `结论卡_*.json` / `底稿_*.json`
- `演示稿_*.html`（模板版）+ `演示稿_*_深度版.html`（T6，AI 逐页编排）
- 仅 `519191` 还有 `fit.json`（持仓拟合，问答会读）与 `navSeries.json`（横向对比的净值缓存）——
  它那次跑了持仓拟合；`510300` 原本就没产出这两个文件，不是漏拷。

**故意没放进来**的东西：

- `演示稿_*.pdf`（两个文件合计约 4.2 MB）—— 仓库体积、构建上下文都扛不住，占比太大而收益只是"能下载 PDF"。
  没有 PDF 时页面已经有一条兜底文案（"打开演示稿按 `P` 自己打印"），行为是对的。
- `_e2e_summary.json`（本机联调残留）、`黄海_*.md`（上一版报告，不在交付物表里）。

总体积 **2.12 MB / 26 个文件**，留了余量。要加内容先看体积：**超过 2.5 MB 就别加了**，
优先砍 `navSeries.json`（124 KB，只给对比页当缓存用）和 `底稿_*.json`（180–270 KB，可复现用，演示时看不到）。

## 怎么来的（要更新就照这个流程重跑一遍）

2026-11-01 在本机 `node server.mjs` 起服务，从页面输代码、按确认后的口径开跑（等价于 `POST /api/run`
跑完整流程：采集 → 官方季报 PDF 逐行对账 → 计算 → 质检 → 规则报告 → AI(T1/T2/T3) → 深度演示稿 → 导出 PDF），
产物落在 `_runs/<代码>/`，然后**从中复制**出这里的内容（排除上面列的 PDF 等文件）。

> 所以 `run.json` 里的 `at` 是**真实跑批时间**，不是提交时间、也不是构建时间。

**这些文件是只读的，不要手改。** 手改过的种子和"真跑一次"的结果对不上，
以后排查问题时你会怀疑是代码坏了，其实是数据被人动过。
要更新就：重跑一次 → 把 `_runs/<代码>/` 里对应的文件覆盖到 `_seed/<代码>/` → 同样排除 PDF。

一个已知的小插曲：`519191` 那次 T5（深度复盘报告）**没通过数字回查校验，被整节拦截了**，
所以它没有《深度复盘报告》一节、`run.json` 里 `deepReportGenerated: false`。
这是校验规则在正常工作，不是种子坏了 —— 其他 13 节和两份演示稿都是完整的。

## 服务怎么用它

`server.mjs` 里的 `seedRuns()`，**只在云端模式**（`FUNDCLINIC_CLOUD=1`，或平台注入的
`RENDER` / `PORT` 等）或显式 `FUNDCLINIC_SEED=1` 时执行：

- 遍历本目录下**名字是 6 位数字**的子目录，目标 `_runs/<代码>/` **不存在才**复制；
  已经存在就跳过 —— 真跑出来的结果永远比种子重要，绝不覆盖。
- 复制完在目标目录写 `_seeded.json`（`{seeded:true, from:'_seed/519191', at:…}`），
  `/api/history` 会带一个 `seeded` 字段，据此区分"种子"和"自己跑的"。有人真跑了一只种过的基金，
  这个标记会被删掉 —— 那份内容已经不是种子了。
- 顺手把 `run.json` 里指向本机的**绝对路径**改写成实际容器里的路径，并把找不到文件的条目
  （也就是 PDF）清成 `null` —— 不这么做的话，种子在容器里路径全是 `C:\Users\...`，
  「在线看报告 / 看演示稿 / 下载」会全部 404 或 500，比没有更糟。
- 复制失败不拖垮启动：包在 try/catch 里，只在启动横幅打一行。

**本机模式默认不种**：免得组员自己电脑上突然多出两只"不是我跑的"基金，还以为是自己跑的。
本机想看种子效果就 `FUNDCLINIC_SEED=1 node server.mjs`；想强制关掉就 `FUNDCLINIC_SEED=0`。

## 顺带说一句

这个目录能救的只是**演示**，不是"历史记录"：种子是死的、只补一次，云端真跑过的结果仍然随容器一起消失。
要长期保存得挂持久卷，那是另一件事，不在这次范围里。
